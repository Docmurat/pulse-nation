# Пульс Нации — память проекта

Кидай этот файл (или его начало) в новый чат, чтобы Claude мгновенно понял контекст.
Полная структура, фазы и модель данных — в отдельном документе-структуре проекта.

## Суть
Генеалогическая платформа карачаевского народа. Главный экран — «космос»: каждый
человек это частица-карточка, родственные связи — светящиеся нити. Зум, перемещение,
поиск. Идея: сразу видно, «где что в нации происходит» — отсюда название.

Народ небольшой (~250–350 тыс.), сплочённый, рода реально пересекаются — поэтому
единый граф всей нации технически достижим, в отличие от больших народов.

## Ключевые функции (по фазам)
**Фаза 1 (MVP, сейчас строим):** визуализация-космос, карточка человека
(ФИО, пол, год/возраст), добавление семьи мастером, поиск, обнаружение совпадений
и слияние дубликатов, регистрация и роли.

**Фаза 2:** режимы отображения (плоское древо / возрастная шкала / карта локаций),
расширенные поля карточки, правки чужих данных с согласованием, кабинет модератора,
донаты.

**Фаза 3:** «пульс» события с уведомлением родни до N колена (с модерацией),
праздничные нити при свадьбе, навигатор родства («5 рукопожатий»),
вики-карточки известных людей (заявка → оплата → 20 голосов), тамги родов (платно), PWA.

**Фаза 4:** мобильные приложения (Android/iOS через Capacitor), публикация в сторы.

## Четыре режима отображения графа
1. Космос (основной) 2. Плоское древо семьи (с расширением до двоюродных/троюродных)
3. Возрастная шкала (дети внизу, старшие и ушедшие вверху) 4. Карта локаций.

## Монетизация
Цель — окупить хостинг, не прибыль. Донаты + платные украшения (выделение карточки
через голосование сообщества, тамга рода). Понты стоят денег, но через модерацию.

## Технологии
React+Vite (JS) · d3-force/Canvas · Node.js · Yandex PostgreSQL · Yandex Cloud ·
GitHub (приватный репо Docmurat/pulse-nation) · разработка в VS Code на Windows.
SQL-запросы выполняем в **WebSQL Яндекса** (не DBeaver — основателю неудобен).

## Архитектурные решения (важные договорённости — не нарушать)
- **Модель родства:** в базе храним ТОЛЬКО связи «родитель→ребёнок» и «супруги».
  Братья/сёстры отдельно НЕ хранятся — выводятся через общего родителя (любого:
  отца ИЛИ мать). В космосе у человека — СПИСОК родителей (не две ячейки);
  связь родитель→ребёнок независима от брака родителей.
- **Поиск кратчайшего пути («N рукопожатий», фаза 3):** комбинация подходов 2+3.
  (3) При загрузке графа приложение достраивает виртуальные рёбра брат-сестра
  В ПАМЯТИ (не в базе), пробегая по общим родителям.
  (2) Рёбрам задаются ВЕСА: родитель↔ребёнок = 1, супруги = 1, брат↔сестра = 1.
  Иначе алгоритм посчитает родного брата за 2 шага (через родителя). Путь к мужу
  сестры: брат→сестра→муж (2 шага), не брат→отец→сестра→муж (3). УЧЕСТЬ ОБЯЗАТЕЛЬНО.
- **Род определяется АВТОМАТИЧЕСКИ, поля в форме НЕТ:** отец из базы → его род;
  отец новый с фамилией → род = фамилия во множ. числе (Курджиев→Курджиевы);
  фамилия только ручная → род из неё + пометка clan_unverified + запись в
  review_queue (тихо, без комментариев в форме — они могут обидеть). Сущность
  «род» в базе остаётся (тамги; объединение нескольких фамилий в один род — позже).
- **Наследование:** отчество детей от имени отца (словарь исключений PATR_EX в
  server/index.js — легко пополнять; общее правило: согласная +ович/овна, гласная
  +евич/евна, «-ий» у карачаевских имён сохраняет «и»: Таубий→Таубиевич; русские
  Валерий/Юрий/Василий и пр. — в словаре). Фамилия: сыновья мужская, дочери
  женская форма (feminizeSurname). Ручная фамилия вводится в мужском роде,
  сервер приводит сам (masculinizeSurname).
- **Прозвон дублей (умная проверка) — РАБОТАЕТ в форме:**
  • GET /api/check-person: нечёткие имена (нормализация о/у, вхождение,
    расстояние редактирования ≤1 при совпадающей ПЕРВОЙ букве), пол, год ±3
    (год берётся и из полной даты), сверка ОТЦА и МАТЕРИ кандидата (по связям
    или корню отчества) — чужие родители отсеивают кандидата; без родителей — оставляют.
  • Форма прозванивает всех (отца/матерей — на blur имени/года; детей — на
    «+ребёнок», «+мать», «Сохранить»). Жёлтая плашка: «Да, это он» (берётся
    карточка из базы; ребёнок → existing_id, сервер не создаёт дубль, только
    доращивает связи) / «Нет, это другой человек». Сохранение блокируется,
    пока висят неразобранные плашки. АВТОМАТИКА НИКОГДА НЕ СЛИВАЕТ САМА.
  • Расхождения введённого с базой (фамилия/год/жив-умер) → POST /api/review →
    таблица review_queue (kind: data_mismatch / clan_unverified; details jsonb;
    status open). Смотреть: GET /api/review. Это заготовка кабинета модератора.
  • ПОСЛЕ сохранения семьи — тихая проверка checkFamilyOverlap: если ≥2 новых
    детей совпали с детьми одной существующей семьи (а родители другие) →
    review_queue kind family_overlap («не одна ли это семья?»). Один совпавший —
    шум (тёзка), записка не создаётся. Проверка не может сломать сохранение.
- **Форма «Добавить семью»:** режимы человека: «из базы» (ПО УМОЛЧАНИЮ) /
  «новый» / «неизвестен» (режим «только имя» УБРАН — в «новом» все поля
  необязательны, можно ввести одно имя); пол ребёнка — иконки-кнопки 👦/👧
  (голубая/розовая, выбранная цветная); «ушёл из жизни» — кнопка 🌙 справа от
  даты рождения (выкл — серая, вкл — золотая), даты смерти раскрываются
  ОТДЕЛЬНОЙ строкой ниже; ЖИВОЙ по умолчанию. Семья сохраняется И БЕЗ ДЕТЕЙ
  (достаточно одного человека). Многожёнство: «+ добавить мать». Брачная нить
  только при «в браке»; при «в браке» у новой матери галочка «взяла фамилию
  мужа» (своя → в девичью). Поиск из базы показывает отчество, год, ☾ и ОТЦА
  кандидата (тёзки различимы). Подложка формы: scrollbar-gutter stable
  (панель не дёргается при росте контента).
- **Приватность дат:** полная дата хранится, наружу НИКОГДА не отдаётся;
  сервер отдаёт год и ТОЧНЫЙ возраст (посчитан по полной дате в SQL);
  умершим — точный возраст на момент смерти age_at_death (по двум полным
  датам), иначе космос считает приближённо по годам. На чипе вторая строка:
  «Фамилия · N лет» (живым — сейчас, ушедшим — сколько прожил); в карточке
  ушедшего: «1890 — 1957 · прожил(а) 67 лет».
- **Космос:** клик по человеку — ЕГО семья ярусами по центру экрана на весь экран
  (centerFamily): родители сверху, братья/сёстры (родные и по одному родителю)
  с ним в один ряд ПО СТАРШИНСТВУ, супруг(а) сразу справа от него, дети снизу.
  Любой клик перестраивает сцену вокруг кликнутого (решение основателя;
  прежнее «спокойные клики по своей сцене» ОТМЕНЕНО, функция inCurrentScene
  убрана). После сохранения семьи — автопоказ её (записка pulse_focus_id в
  sessionStorage). Попадание курсора/клика — по ВСЕЙ площади чипа.
- **Пол в данных:** m/f; космос дополнительно понимает м/ж (normG), но базу
  держим в m/f.

## Как запустить проект локально (памятка)
Два терминала в VS Code:
1. Сервер: cd C:\dev\pulse-nation\server → node index.js (порт 3001)
2. Космос: cd C:\dev\pulse-nation → npm run dev (порт 5173)
http://localhost:5173. База не отвечает → проверить VPN (Happ). Секреты в
server/.env (в git не попадает). После правок server/index.js сервер
ПЕРЕЗАПУСКАТЬ (Ctrl+C → node index.js).
